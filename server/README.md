# Hebrew CoreS3 cloud relay

Status: implemented and deployed as a **private staging service**, not connected to the device.
Provider keys are intentionally pending; authenticated readiness reports not configured.
Provider tests use controlled HTTP responses, not live billable services.
The existing firmware and experimental binary remain unchanged.

## Run and test

Python 3.11 or 3.12:

```sh
python -m venv .venv
# Activate the virtual environment for your shell.
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
uvicorn relay.app:default_app --factory --host 127.0.0.1 --port 8080 --no-access-log
```

Set environment variables from `.env.example` privately, or use Secret Manager mappings in Cloud Run.
The template is not loaded automatically. Never commit filled settings.
`/health` checks process liveness; `/ready` checks configuration only and never makes billable probes.
Neither endpoint proves live provider access or production readiness.
The legacy `/healthz` and `/readyz` routes remain for compatibility, but should not be used for
Cloud Run probes: Google Frontend reserves some z-ending paths and intercepted `/healthz` with404.
See https://docs.cloud.google.com/run/docs/known-issues#reserved-url-paths.

## Contracts

`POST /v2/turn`: body is WAV, mono PCM16 at 16kHz, at most 1,000,000 bytes and 30 seconds.
Auth: `X-Device-Secret` (at least 32 characters in server configuration).
Optional `X-Request-ID`: UUID generated by device before upload, needed for cancellation.
Optional `X-Profile`: `private` (default) or explicitly `playground`.
Clients cannot select models, keys or arbitrary providers in requests.

Successful JSON:

```json
{
  "version": 2,
  "request_id": "opaque-uuid",
  "profile": "private",
  "transcript": "שלום",
  "answer": "שלום, אני שומע אותך.",
  "sources": [{"title": "Source name", "url": "https://example.org/"}],
  "audio": {"mime_type": "audio/wav", "base64": "..."},
  "timings": {"stt_ms": 100, "llm_ms": 200, "tts_ms": 100}
}
```

`POST /v1/turn` uses the same request and returns only `audio/wav`.
`DELETE /v2/turn/{request_id}` with the device secret cancels an active upload/provider turn.
A cancelled POST returns 409. Cancellation cannot undo charges already incurred at a provider.
Requests and outputs use `Cache-Control: no-store`.

Status codes: 204 short/silent input or empty transcript; 400 invalid ID/profile; 401 auth failure;
409 duplicate/cancelled request; 413 oversized input; 415 wrong media type; 422 invalid WAV;
429 busy/local quota; 502 sanitized upstream failure; 503 unconfigured or private route unapproved;
504 total turn deadline, including upload. Failures contain an opaque request ID; upstream errors
also identify the stage without exposing provider bodies.

## Provider configuration and privacy

- Groq Whisper large-v3: Hebrew multipart transcription.
- OpenRouter: operator-selected `LLM_MODEL`, constrained by `ALLOWED_MODELS`.
  Private requests send `data_collection: deny`, optionally require ZDR (default true), and disallow fallback.
- Tavily: optional `TAVILY_API_KEY`; one basic search maximum per turn, at most four validated source URLs.
  No search tool is advertised without its key. Search failure produces an error, not invented current facts.
- Azure Speech: Hebrew Hila voice, escaped SSML and 16kHz mono PCM WAV.

Private mode fails closed until `PRIVATE_PROVIDERS_APPROVED=true`. This flag records an operator
decision after reviewing **all four** providers; it does not itself establish their contractual terms.
Playground has no server personal memory/persona/documents. It still transmits the spoken utterance;
it is not an automatic detector or remover of sensitive speech.
No transcript, answer, API key or raw provider error is logged by the relay. Only request IDs,
stage labels, timings and byte counts are logged. Production ASGI access logging is disabled.

## Limits and deployment gates

One turn at a time per process. Upload plus all providers share a 45-second deadline.
Input RMS filtering reduces silence hallucinations but is not full voice activity detection.
Replay prevention (10 minutes), request counters (default 6/minute, 100/day), and admission locks
are **in memory**: they reset on restart and do not coordinate replicas.
When the bounded replay cache fills, new IDs receive429until entries expire; unexpired IDs are never evicted.
This is defense in depth, **not a hard spending cap**. Before public production deployment,
configure durable distributed limits or independently enforced provider/spend caps.
Set Cloud Run max instances=1, concurrency=4 and min instances=0, with one ASGI worker.
HTTP concurrency must exceed one so cancellation and health requests can reach a busy instance;
the application still admits only one voice turn. These settings alone do not cap costs.
Build, registry, network, logs and other cloud resources can also incur charges.

Current turns are stateless. Conversation history, streaming, persistent memory, actions and the
CoreS3 relay adapter are subsequent work; there is no claim that the device already calls this server.
Base64 WAV is bounded to 1.5MB of audio and adds about one third in JSON transfer size.
Future streaming can reduce latency and memory use without replacing the local UI.
