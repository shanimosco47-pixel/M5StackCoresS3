# מצב העבודה — 21 בנובמבר 2026

## עובד ואומת על ה־CoreS3

- הוחלפה קושחת OpenAI הישנה ב־stackchan-idf v0.14.3 הרשמית של הפרויקט.
- התחברות ל־Wi-Fi ול־OpenAI Realtime, זיהוי דיבור והשמעת תשובות בעברית אומתו בלוגים ובאישור המשתמש.
- המשתמש אישר שהפנים מוצגות ושנשמעת תשובה מהרמקול.
- עוצמת הרמקול הוגדלה בהגדרות מ־80 ל־180; טרם התקבל אישור סופי לאיכות העוצמה.
- הופעלה הגדרת `bargein_en=1`; המשתמש אישר שהקשה במרכז קוטעת מיד ושפינה שמאלית משתיקה.
- גיבוי מקורי מלא של 16MB נשמר מקומית לפני הצריבה. הוא מכיל סודות ולכן אינו במאגר.

## מומש ונבנה, עדיין לא נצרב ולא אומת על המכשיר

- גופן עברי 12/24px ו־Unicode bidi לכתוביות מעורבות עברית/אנגלית/מספרים.
- חיפוש קולי דרך OpenAI Responses עם מקורות, מגבלות גודל וזמן וטיפול בביטול ובשגיאות.
- ברירת מחדל לקול `gpt-realtime-2.1-mini`; חיפוש `gpt-4.1`.
- הודעת סיום בעברית, חד־פעמית, מופעלת רק באמצעות `update_notice=1` ב־NVS.
- בניית ESP-IDF 5.5.5 הסתיימה בהצלחה; קובץ האפליקציה ותיאורו ב־`artifacts/`.
- הבדיקות המקומיות עברו; ראו VALIDATION.md. אין להסיק מכך שהחיפוש כבר עובד על המכשיר.

## כיוון המשך שהמשתמש ביקש

המשתמש ביקש אפשרות חינמית ואישר לבדוק Gemini Live לשיחה ו־Tavily לחיפוש.
דפי שני השירותים נבדקו והציגו דרישת התחברות; לא נוצרו מפתחות ולא הוטמע החיבור החדש.
לאחר מכן הוצג מסמך שרת מתווך בענן. הכיוון המומלץ הוא להוסיף מתאם שרת
לקושחה הקיימת ולשמר את הפנים, המגע, העברית והקטיעה, במקום להחליף אותן בדמו Arduino.
המשתמש אישר לשמור את העבודה במאגר זה. אין כרגע שרת ענן שנפרס במסגרת העבודה הזאת.

## השרת המתווך — התקדמות חדשה

מומש שרת FastAPI עם `/v1/turn` לאודיו ו־`/v2/turn` לטקסט עברי, מקורות ואודיו יחד.
מומשו חיבורי Groq, OpenRouter, Tavily ו־Azure, אימות מכשיר, בדיקת WAV,
מגבלות העלאה, סינון שקט, ביטול בזמן העלאה/עיבוד, הגנת בקשות כפולות וניתוב פרטי מוגבל.
34 בדיקות שרת מקומיות עברו, כולל תגובות HTTP מבוקרות של ספקים, ועוד 8 בדיקות לשער הסקירה ב־GitHub.
אין עדיין בדיקת ספקים אמיתית לשרת החדש.
סוקר נפרד מצא ותיקנו שלוש תקלות בזמן העלאה וביטול, ואישר בבדיקה חוזרת שהתיקונים תקינים.
Ruff, בדיקת Bandit ברמות בינונית/גבוהה וסריקת התלויות המלאה עברו.
בדיקות GitHub עברו בשתי גרסאות Python וגם בסריקות האבטחה.
Copilot התברר כלא זמין בחשבון, אך בוט Codex מחובר והשלים סקירה עצמאית אמיתית של PR1.
הסקירה מצאה בעיית תפוגת הגנת בקשות כפולות במטמון מלא; היא שוחזרה בבדיקה ותוקנה.
שער הבדיקה של Codex אומת בפועל על a882bb6: סקירה הסתיימה ללא ממצאים, וכל בדיקות GitHub עברו.
כל קומיט חדש עדיין דורש סקירה חדשה על ראש ה־PR העדכני.

המשתמש יצר פרויקט חדש **M5Stack**, מזהה `m5stack-515405`, במקום `hey-usa`.
הפרויקט שויך לחשבון החיוב החדש והפתוח, ושירותי הבנייה, Cloud Run וניהול הסודות הופעלו.
נוצרו זהויות נפרדות לבנייה ולריצה, והוכנו מכולות סודות. סוד מכשיר נוצר בלי להציגו.
אומתה תקרת Cloud Run חודשית של5ILS במצב CONFIGURED והתראת עלות כללית בסכום זה.
בנייה, אחסון וספקים חיצוניים אינם נכללים בעצירת Cloud Run; ההתראה הכוללת אינה תקרה קשיחה.
שירות בדיקה פרטי נפרס באזור europe-west1. המוכנות שלילית משום שאין עדיין מפתחות ספקים.
בדיקה חיה איתרה חסימת `/healthz` על ידי Google Frontend; נוספו `/health` ו־`/ready` המתאימים לענן.
גרסאות ותוצאות בדיקות חיות נשמרות ב־PR1; ראו CLOUD_DEPLOYMENT.md לשחזור ובדיקת הפריסה.
המשתמש הודיע שיפתח מפתחות בהמשך. לא הוחלף ספק במכשיר ולא נצרבה קושחה חדשה.
מגבלות השימוש של השרת הן בזיכרון התהליך ואינן תקרת חיוב קשיחה.

## להמשך

1. להמתין למפתחות הספקים שהמשתמש יפתח בהמשך, ולהזין אותם ב־Secret Manager דרך כלי הקלט המוסתר.
2. לאמת קריאת API אמיתית לפני שינוי פרטי הגישה במכשיר.
3. להשלים את הגדרות המודל, הפרטיות ומגבלות הספקים ולהוסיף מתאם למכשיר תוך שמירת התכונות הקיימות.
4. לבדוק על המכשיר עברית קריאה, חיפוש עם מקור, שיחה, השתקה וקטיעה.
5. רק לאחר הצלחה להפעיל את הודעת סיום העדכון ולוודא שנשמעה.

מסמכי התכנון המקוריים מתעדים הצעות ומצב היסטורי; קובץ זה הוא מצב העבודה העדכני.
